## [0.2.0] - 2026-09-28

### Added

- `scripts/testnet` deploy and season scaffold (Sprint 1.8, P1.8.6): `deploy.sh` builds, deploys, and wires all five contracts on Stellar testnet with Address only arguments, and `season.sh` drives one rainfall season as named stages that wait out the seven day publisher registry timelock and the twenty four hour challenge window, with placeholders for the complex typed arguments and a note on signing observations off chain; a `README.md` documents the prerequisites and the staged run. This is the deferred live testnet half of Phase 1 exit criterion 1, authored for the owner shell (DR-0028).
- `integration-tests` crate (Sprint 1.8, P1.8.4): an end to end test that registers all five contracts on one Soroban test host, wires them as a testnet deployment would (`set_policy_contract` and `set_payout_vault` on risk-pool, `set_oracle` on trigger-engine), and drives a full rainfall season from a junior capital deposit and premium intake through two registered publishers' signed observations, the on chain `oracle-adapter.median` feed, `trigger-engine` evaluation and finalization after the challenge window, a `payout-vault` batch payout, and the farmer's claim, reconciling season `payouts_paid` and pool reserves at the end; a second test proves a healthy season blocks any payout because the unfinalized window traps `pay_batch`. Ledger time is advanced to clear the publisher registry timelock and the challenge window a live testnet run waits out in wall clock time (DR-0028).
- `risk-pool` pool creation (`create_pool`): validates configuration, allocates a monotonic pool id, and initializes both tranches, the solvency record, and the treasury to zero (guardian only).
- `risk-pool` tranche deposits (`deposit`): moves the pool token in and mints pro rata receipts, one to one into an empty tranche and pro rata to the existing supply thereafter, with per tranche caps.
- `risk-pool` withdrawals (`withdraw`): burns receipts and releases the underlying, rejected when it would break the solvency invariant `reserves >= committed`, and blocked for the senior tranche while any payout is committed.
- `risk-pool` read helpers (`pool_config`, `tranche`, `receipt`, `solvency`) and unit and property tests covering the deposit, withdrawal, and solvency guard paths.
- `risk-pool` season lifecycle (`open_season`, `activate_season`, `close_season`): a strictly forward state machine `Open` to `Active` to `Closed` to `Settled` with monotonic per pool season ids, guarded transitions, and lifecycle events.
- `risk-pool` premium intake (`collect_premium`): authenticates the payer, accrues capped protocol and publisher fees to the treasury, moves the pool token in, and credits the net premium to the open season and to solvency reserves.
- `risk-pool` season settlement (`settle_season`): guardian only, permitted only on a closed season, applies the settlement waterfall by crediting surplus entirely to the junior tranche and absorbing losses junior first then senior, and returns the realized net.
- `risk-pool` fee configuration (`FeeConfig`) on the pool with validated protocol and publisher basis points and caps, plus `season` and `treasury` read helpers, new error codes `InvalidSeasonState` (110) and `SeasonNotFound` (111), and unit tests covering the lifecycle, fee accrual and caps, and the surplus and loss waterfall paths.
- `risk-pool` premium quote (`premium_for`): a read only provisional linear curve `base_bps + coverage_slope_bps * floor(coverage / unit)`, rounded up so integer truncation never underprices the pool (DR-0022).
- `risk-pool` premium refund (`refund_premium`): reverses the reserved net from the season and reserves and pays it back, guarded by a registered policy contract (`set_policy_contract`, `policy_contract`) and the solvency invariant, with a `PremiumRefunded` event; fees are not reversed.
- `policy` certificate lifecycle (Sprint 1.4): `quote` and `mint` (quotes against the pool curve, checks the buyer's `max_premium`, collects the premium, and mints an `Active` certificate), the state machine `mark_triggered`, `mark_paid`, `expire`, and owner `cancel` with a net premium refund before the coverage window opens.
- `policy` off chain metadata pointer (`set_metadata`, `metadata`): an opaque `BytesN<32>` reference with no PII on chain (NFR-PRIV-1), plus `policy` and `risk_pool` read helpers, error codes 200 to 207, and unit tests covering quoting, minting, the full lifecycle, cancellation and refund, and metadata.
- `policy` cooperative batch purchase (`mint_batch`, Sprint 1.5): a single payer funds and authorizes a bounded list of entries (`BatchEntry`), each minting a policy for its own owner; the call is atomic and capped at `MAX_BATCH`, rejecting an empty or oversized batch with `InvalidBatch` (208), and emits a `BatchMinted` summary (DR-0023).
- `policy` transferability (`set_transferable`, `transferable`, `transfer`): a per pool flag defaulting to non transferable that the guardian sets, with an owner `transfer` permitted only when the pool allows it and only while the policy is `Active`, emitting `PolicyTransferred` and `TransferabilitySet`, plus unit tests covering batch mint, size limits, per entry price caps, and the transfer guards.
- `oracle-adapter` publisher registry (Sprint 1.6): a timelocked `propose_publisher`, `execute_publisher`, and `cancel_publisher` flow (provisional 7 day timelock) keyed by ed25519 public key, where a removal deactivates rather than deletes so observation history keeps a resolvable author (DR-0024).
- `oracle-adapter` signed observation ingestion (`submit`): authenticates a submission by verifying an ed25519 signature over the XDR of the observation payload rather than by `require_auth`, rejects a negative value or future timestamp with `InvalidObservation` (308), and writes the observation into a fixed size overwrite ring (`RING_SIZE` = 16) per region and metric.
- `oracle-adapter` trusted median (`median`): aggregates the median over accepted, unchallenged, and fresh observations and returns `ObservationStale` (302) unless at least `MIN_PUBLISHERS` (2) distinct publishers are represented and the freshest data is within the staleness bound (default 48 hours), so a stale or under sourced index blocks a trigger.
- `oracle-adapter` guardian challenge (`challenge`, `unchallenge`) that excludes a ring slot from the median, read helpers (`is_publisher`, `publisher_info`, `pending_publisher`, `observation`, `head`, `is_challenged`, `staleness_bound`), new error codes 305 to 308, and unit tests that sign real payloads with `ed25519-dalek` (dev dependency) to exercise the verification, forgery, median gate, staleness, and challenge paths.
- `trigger-engine` index definitions (`create_index`, Sprint 1.7): an immutable first class `IndexDefinition` (rainfall shortfall or consecutive dry days) validated per kind, with a monotonic `index_id` and no update path, rejecting a definition that could never evaluate deterministically with `InvalidIndexDef` (405) (DR-0025).
- `trigger-engine` daily ingestion (`record_day`): folds each day's median into a bounded per window `WindowAccumulator` (cumulative rainfall and the longest consecutive dry run) in one pass, requiring strictly increasing days and rejecting a replay, out of order day, negative value, or overrun with `NonDeterministicInput` (404); guardian fed in this sprint, with the `oracle-adapter.median` cross call deferred to Sprint 1.8.
- `trigger-engine` deterministic evaluation (`evaluate`): pure integer rainfall shortfall and consecutive dry day formulas computed in basis points matching INDEX-SPEC and golden vectors G1 to G8, returning `StaleIndex` (401) on an incomplete window so a payout can never fire on partial data, and moving a breached window from `Healthy` to `Triggered` idempotently.
- `trigger-engine` finalization and payout (`finalize`, `payout_for`): a guardian only, irreversible transition to `Finalized(at, severity)` permitted only after a provisional 24 hour challenge window (`TimelockPending` before then, `AlreadyFinalized` and `NotTriggered` guards), and a severity scaled payout `min(coverage, coverage * severity / BPS)` rounded down to favor the pool, plus read helpers (`index_def`, `trigger_state`, `accumulator`, `index_count`), events (`IndexCreated`, `DayRecorded`, `Triggered`, `Finalized`), and 18 unit tests covering the golden vectors and the full lifecycle.
- `risk-pool` guarded payout release (`pay_out`, `set_payout_vault`, `payout_vault`, Sprint 1.8): the sole registered payout-vault address may draw an amount from a pool's reserves, which decrements reserves under the solvency invariant, records the amount against the season's `payouts_paid` so `settle_season` still reconciles, transfers the underlying to the vault, and emits `PayoutReleased`; permitted only on an `Active` or `Closed` season (DR-0026).
- `payout-vault` resumable batch payouts (`pay_batch`, `close_batch`, Sprint 1.8): a guardian pays a bounded batch (`MAX_BATCH` = 20) of guardian asserted entries (`PayoutEntry`), confirming each on chain through the trapping `trigger-engine.payout_for`, drawing funds via `risk-pool.pay_out`, and crediting each holder's `Claim` ledger; entries are idempotent by `Payout(policy_id)` so an overlapping retry is safe, a window is resumable by client chunking against a `Batch(index_id, window_id)` checkpoint, and a closed batch rejects further payouts with `BatchComplete` (501) (DR-0026).
- `payout-vault` holder claims (`claim`, `claimable`): a permissionless push of a holder's accrued balance to their address that never requires the holder's XLM or signature, zeroing the ledger before the transfer, the Soroban equivalent of a classic claimable balance since the network has no host function to mint one (DR-0026).
- `payout-vault` emergency pause (`pause`, `unpause`, `is_paused`, FR-PAY-5): a guardian flag that blocks `pay_batch` while set but never blocks `claim`, so an already recorded payout can always be collected, plus read helpers (`admin`, `payout`, `batch`), events (`PayoutRecorded`, `Claimed`, `PauseSet`), error codes 500 to 506, and unit tests covering the pay, claim, idempotent retry, multi owner, unbreached window, pause, close batch, and post season close paths against the real `risk-pool` and a mock trigger.
- `trigger-engine` integrated oracle median feed (`record_day_from_oracle`, `set_oracle`, `oracle`, Sprint 1.8): the guardian records a day by reading the trusted median from `oracle-adapter` on chain for the index's own region and metric, rather than asserting the value; a stale or under sourced oracle traps the cross call so no day is folded, and the guardian `record_day` feed is retained as a fallback sharing the same reduction, with a new `OracleNotConfigured` (406) error, an `OracleSet` event, and six unit tests against a mock oracle including the stale fail safe (DR-0027).
- Contract workspace scaffold (Sprint 1.1): the five contract crates `risk-pool`, `policy`, `oracle-adapter`, `trigger-engine`, and `payout-vault`, each with its `DataKey` storage layout, `#[contracterror]` error enum in its documented code range, and a guardian constructor.
- `common` shared library crate: the shared error code range (900 to 999), basis point math, and storage TTL bump and extend helpers, linked into every contract.
- `test-utils` shared library crate: environment and ledger fixtures, time and sequence advance, and assertion helpers for contract tests.
- Architecture document (`docs/ARCHITECTURE.md`): module map, key flows, storage layout per contract, error model with per contract code ranges, authorization model, and upgrade pattern.
- Threat model (`docs/THREAT-MODEL.md`): assets, trust boundaries, adversary list, and twenty threats with mitigations mapped to requirement IDs.
- Index definition specification (`docs/INDEX-SPEC.md`): rainfall shortfall and consecutive dry days formulas with integer math, severity curve, staleness rules, and golden test vectors.
- Upgrade and governance specification (`docs/UPGRADE-GOVERNANCE.md`): guardian multisig responsibilities, timelock flow, and per contract migration procedures.
- Brand assets in `assets/` (raindrop logo, horizontal lockup, and a system map README banner) and a rewritten README with the project system diagram, the repository's place in the whole project, per crate status, and a summary of the implemented risk-pool lifecycle.
